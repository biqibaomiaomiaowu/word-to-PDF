# 如何复现并验证“智能去除末尾广告”修复效果

此文档用于说明如何在本地复现“末尾全屏/海报图片广告”的失败样本，并验证修复效果。

## 1. 为什么原逻辑会失败？

原始版本中，智能去除末尾广告主要依赖于 PDF 转换后的**文本层**提取，并固定扫描 PDF 的 **底部 35%** 区域。它通过查找诸如 `扫码`、`微信`、`免费领取` 等关键字来判断是否为广告。

在您的样本中：
1. 广告是一整张大图片（海报/宣传图），且位于最后一页，占据了下半页的很大一部分。
2. 因为是纯图片，`fitz` 的 `get_text()` 提取不到关键词。
3. 即使该图片有二维码，该二维码也不是一个“独立的小图片对象”，而是嵌在整张海报大图里。
4. 广告高度可能超出了底部 35% 的扫描范围。

因此，原逻辑（仅通过文本层关键词匹配和固定小范围搜索）会直接漏检。

## 2. 现在的两阶段修复方案

我们实现了 **两阶段去广告** 策略：

**阶段 1：DOCX 预清理（主方案）**
在 LibreOffice 转换之前，使用 `python-docx` 解析源文件。
1. 查找文档尾部的最后几个段落。
2. 过滤掉空段落，定位到最后一个非空段落。
3. 如果该段落通过底层 XML（`w:drawing`, `w:inline`, `a:blip`）被判定为“纯图片/海报”段落，且该图片上方存在正常的正文文本（确保不是全篇只有图片的文档），则将该图片及其后面的空段落全部删除。
4. 将清理后的临时 `.docx` 文件送给 LibreOffice 转换。

**阶段 2：PDF 兜底清理（辅方案）**
如果输入的是已有 PDF（或 DOCX 清理未能拦截），转换后会在 PDF 末页进行兜底。
1. 将底部扫描范围扩大至 **55%**（`y >= 0.45 * page_height`）。
2. 在该区域不仅搜索文本关键字，还会扫描提取图片。
3. 寻找符合“海报”特征的大图片（宽 >= 页面宽 40%，高 >= 页面高 15%），且位于下半部分。
4. 如果命中该特征，判定为广告海报，并将页面从图片顶部上方进行**裁剪**。

如果任何阶段发生解析异常，任务不会直接 Failed，而是会输出报错日志并降级继续。最后通过前端界面（`去除广告(DOCX)` / `去除广告(PDF)`）向用户展示处理结果。

## 4. 边界风险与注意事项

1. **内联图片 vs 浮动图片**: DOCX 清理方案目前基于 `python-docx` 段落级别（Paragraph）查找内联图形或固定图形。如果是使用极为复杂的高级“浮动锚点”且完全脱离段落顺序的图片，可能会漏过阶段1，但在阶段2（PDF兜底）会被大图识别拦截。
2. **正文误删**: DOCX 阶段要求图片必须是文档末尾的“最后一个非空段落”，如果正文结束后，用户又打了一行“谢谢观看”的文本，那最后一段就不再是纯图片段落，此时 DOCX 预清理会跳过，同样交给阶段 2 兜底。
3. **裁切精度**: PDF 兜底采用的是页面 `CropBox` 裁剪。如果您使用其他编辑器打开 PDF，被裁掉的部分本质上还在文件里（只是不可见），但对于普通阅读器和打印来说是完全去掉的。这属于 PyMuPDF 的标准安全裁剪方式。
